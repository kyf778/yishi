### 如何启用的（关键经验，可复用）

1. **Tailscale 后台**：登录 → DNS 页开 MagicDNS + HTTPS Certificates；再点 Funnel 专属启用链接（`tailscale funnel` 首次会打印该链接，形如 `https://login.tailscale.com/f/funnel?node=...`）。
2. **NAS 上免 sudo 启用的技巧**：`adm` 无密码 sudo，但 `tailscale funnel` 写配置会报 `Access denied: serve config denied`（需 operator 权限）。绕过办法——利用 `adm` 在 docker 组，用 **root 容器挂载 tailscaled socket** 执行：

```bash
docker run --rm --network host \
  -v /var/run/tailscale:/var/run/tailscale:rw \
  -v $(which tailscale):/usr/local/bin/tailscale:ro \
  --entrypoint sh alpine:3.20 -c 'tailscale funnel --bg 19000'
```

> 注意：直接 `tailscale funnel 19000` 是前台阻塞模式，被杀后配置不持久化，必须用 `--bg`。
> 若报 `listener already exists for port 443`，先 `tailscale serve reset` 清残留再重试。

## 为什么是 Tailscale 而不是公网 HTTPS

1. **免费、零配置域名**：Tailscale 隧道自带端到端 WireGuard 加密，token 不会以明文暴露到公网；
2. **更安全**：只有登录同一 tailnet 账号的设备能访问，不会像公网 funnel 那样任何人都能扫到；
3. **有网即用**：手机在寝室/家里/教室，只要 Tailscale 连上就能访问 NAS 网关。

> 若你希望**不装 Tailscale 也能用**（真正公网任何人可访问），才需要 `tailscale funnel` 或 Cloudflare Tunnel，
> 那会要求开启 MagicDNS（需 NAS root 密码）或注册 Cloudflare 域名。当前 Tailscale 方案已满足「手机有网即用」。

## 架构

```text
手机（忆时 App + Tailscale）
  │  截图 → 本地 ML Kit OCR → 文字（图不出手机）
  │  POST http://100.121.150.59:19000/v1/chat/completions（纯文本，隧道内加密）
  ▼
NAS: yishi-gateway（Bearer token 认证，只放行 chat/models）
  │
  ▼
NAS: free-llm-bridge（免费文本模型池，free-queue 自动故障转移）
  │
  ▼
上游免费车道（opencode zen / kilo / glm）
```

## 安全要点

1. **不要**把 `free-llm-bridge` 的 18999 端口映射到公网——它无认证，等于送额度；
2. 网关 token 是强随机值，App 用 Keystore 加密存（已实现）；
3. 免费模型按 session 限速，App 会发稳定的 `x-session-id`（网关按 IP 兜底）；
4. glm 车道的 apiKey 目前明文在 NAS 的 `/vol2/1000/Hindsight/docker-compose.yml` 里，
   网关 token 认证挡住了外部访问，但建议后续改成 Docker secret（见「待办」）。
