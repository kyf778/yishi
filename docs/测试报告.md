### 🔴 Bug 9：10 分钟后的提醒一条都排不上（最严重）

**现象**：建一个 10 分钟后截止的事项，到点没有提醒。

**根因**：默认提醒提前量是「提前 1 天、提前 1 小时」（`listOf(1440, 60)`），
而代码里有 `if (trigger > now)` 的过滤：

```
10 分钟后截止 → trigger(提前1440分钟) = 早已过去 ❌
              → trigger(提前60分钟)   = 早已过去 ❌
              → 提醒数为 0，一条都没排上
```

**修复**：新增 `adaptiveReminders()`，按剩余时长自适应：

| 剩余时长 | 排定的提醒 |
|---|---|
| ≤ 5 分钟 | 提前 1 分钟 |
| ≤ 30 分钟 | 提前 5 分钟、1 分钟 |
| ≤ 2 小时 | 提前 30 分钟、5 分钟 |
| ≤ 24 小时 | 提前 60 分钟、10 分钟 |
| 更长 | 提前 1 天、1 小时（原默认） |

**实测验证**：建了个 3 分钟后的事项，`dumpsys alarm` 里确认排入了系统闹钟：

```
RTC_WAKEUP com.kyf778.yishi
  origWhen=2026-10-17 02:01:00.000
  tag=*walarm*:com.kyf778.yishi.action.FIRE_REMINDER
```

到点后系统日志 `Notify_NotificPush: Start onNotificationPosted pkg=com.kyf778.yishi`，
通知确实弹出来了。

### 🔴 Bug 10：短时间显示成「0 小时」

**现象**：卡片显示「还剩 0 小时」，完全看不出还剩多久。

**根因**：只按天/小时两个单位算，`10 分钟 → remainHours = 0`。

**修复**：新增 `formatRemaining()`，按量级自动选单位（分钟/小时/天）；
另外新增 `formatDeadlineFriendly()`，把「2026-10-17 01:30」显示成「**今天 01:30**」。

### 🟡 Bug 11：摘要「今天凌晨一点半去」很奇怪

模型把截止时间换个说法又写进了摘要。已在提示词禁止项里明确列入，
并加了反例：「今天凌晨一点半去（只是把 deadline 换个说法）」。

### ✅ 新功能：提醒记录

**背景**：`notification_log` 表早就建好了，但**从来没有任何代码往里写** ——
所以用户完全不知道提醒到底有没有生效。

**实现**：`ReminderReceiver` 每次触发都落一条记录，分三种结果：
- `SHOWN` — 正常弹出
- `SKIPPED_NO_PERMISSION` — 通知权限被拒（记录原因，用户可查）
- `FAILED` — 异常，带错误信息

新增「提醒记录」标签页，倒序展示：事项标题 / 结果 / 触发时间 / 计划时间。

**实测验证**：

```
共 1 条提醒记录（最近的在上面）
2
已提醒
触发时间：今天 02:02
计划时间：今天 02:01
```

### ⚠️ 新功能：语音输入（受小米 ROM 限制，已优雅降级）

**用户需求**：「还想再加一个语音输入自动识别一串文字然后让ai来理解的」

**实现了两版，都实测过**：

**第一版 SpeechRecognizer API**：
`isRecognitionAvailable = true`，但回调始终返回
`onError code=9 (ERROR_INSUFFICIENT_PERMISSIONS)`，
**即使 App 已确认拿到 RECORD_AUDIO 权限**。
根因：小米 HyperOS 的语音服务是 `com.xiaomi.mibrain.speech`，
权限校验发生在**厂商服务进程**里，不认 App 侧的授权。

**第二版 Intent 方式**（`ACTION_RECOGNIZE_SPEECH`）：
`AsrActivity` 能解析到，但**启动后立刻自行关闭并返回 CANCELED**。
日志：`Toast already killed. pkg=com.xiaomi.mibrain.speech`。
**用 `am start` 命令行直接触发也一样** —— 证明是小米把语音锁给了自家应用（小爱同学）。

**最终方案：优雅降级**
- 保留语音按钮
- 点它 → 尝试系统语音 → 返回 CANCELED 就自动跳到「打字输入」页
- 自动聚焦输入框（键盘弹出）
- 提示：「系统语音在这台手机上不可用，请用输入法键盘上的麦克风按钮说话，或直接打字」

**这条路可行**：手机上装的讯飞/搜狗/百度输入法，键盘自带麦克风按钮，
走输入法自己的语音通道，不受小米限制。

**结论（重要）**：国产 ROM 上做语音输入，无论用 SpeechRecognizer 还是 Intent 都可能被拦。
输入法麦克风是更可靠的兜底方案，不要在系统语音 API 上死磕。

### 🟡 附带修复：全角日期

中文输入法手输日期会产生全角字符（`2026－12－12 09：00`），
旧代码严格匹配半角格式 → 解析失败 → 保存按钮点了没反应。

**修复**：`DeadlineParser` 加全角归一化（`－：／．` + 全角数字 + 全角空格 → 半角）；
手动新增对话框改用同一解析器，并加实时校验（红字提示 + 禁用保存 + 「将提醒：xxx」预览）。

**实测验证**：输入全角 `2026－10－17 02：01`，界面正确显示「将提醒：2026-10-17 02:01」。

## 一、v0.4.0 修复（界面 + 摘要）

### 🔴 Bug 6：AI 摘要肤浅，只是复述原文

**现象**：摘要写「学委唐林在群聊中通知全体成员，下周三16点进行数据库设计的验收，同时也需要提交实验报告」
—— 把原文换个说法重抄，零信息增量。

**根因**：旧提示词只说「提取」，**没说 summary 应该写什么**。

**修复**：明确禁止三类冗余（重复标题、重复日期时间、复述来源），并给正反例。

**效果对比**：

| | 修复前 | 修复后 |
|---|---|---|
| 标题 | 学委唐林：数据库设计验收与实验报告提交 | **数据库设计验收 + 交实验报告** |
| 摘要 | 学委唐林在群聊中通知全体成员，下周三16点进行数据库设计的验收，同时也需要提交实验报告 | **需提交实验报告** |

### 🟡 Bug 7：主界面排版混乱、卡片不好看

参考番茄 Todo 重设计：渐变主题卡（按类型配色 + Canvas 画月牙/流星装饰）、
进度条、「已过 X/Y 天」；移除顶部的死按钮（`onClick = { }` 空实现）。

## 二、v0.2.2 修复的 Bug

### 🔴 Bug 1：长截图识别失败（你反馈的问题）

**现象**：微信群通知截图（含「下周三16点数据库设计验收」）识别后报「无法识别有效截止时间」

**根因**：不是模型的问题。图片压缩逻辑按「最长边缩到 1600」处理，
一张 1080×5000 的长截图被压成 **345×1600**——宽度只剩 345px，中文字全糊了。
AI 看不清正文，只能认出最显眼的标题「【国奖推荐评审】」，而那条本来就没日期，
所以返回 `deadline=null`。

**实测证据**：

| 处理方式 | 实际尺寸 | 识别结果 |
|---|---|---|
| 缩到 1600（旧） | 345×1600 | ⛔ deadline=null |
| 缩到 2400 | 518×2400 | ✅ 2026-10-21 16:00 |
| 纵向切块 | 1080×1400 ×2 | ✅ 2026-10-21 16:00 |

**修复**：
1. 改为「宽度优先」——先保证宽度 ≤1600px（文字清晰），再纵向切块（每块 ≤1400px，重叠 120px）
2. 强化提示词，要求通读全图所有区域找最早日期
3. 兼容模型返回 JSON 数组的情况（会自动挑出带 deadline 的那项）

**验证**：超长截图（1080×9000，切 7 块）也能准确识别埋在最底部第 7 块里的消息。

### 🔴 Bug 2：日期格式太严格，4 类格式直接崩

**现象**：AI 明明识别出了日期，App 却报「AI 返回的截止时间格式无效」

**根因**：校验只用 `OffsetDateTime.parse` 和 `LocalDateTime.parse`，只认标准 ISO 格式。

**实测**：

| 模型返回 | 修复前 | 修复后 |
|---|---|---|
| `2026-11-05T11:00:00+08:00` | ✅ | ✅ |
| `2026-11-05`（纯日期） | ⛔ 崩 | ✅ → 当天 23:59 |
| `2026/11/05 11:00` | ⛔ 崩 | ✅ |
| `2026-11-05 11:00:00`（空格） | ⛔ 崩 | ✅ |
| `2026年11月5日 11:00` | ⛔ 崩 | ✅ |
| `2026-1-5`（单位数月日） | ⛔ 崩 | ✅ |

**修复**：新增 `DeadlineParser.kt`，支持 8 种格式。纯日期按当天 23:59 处理
（「11月5日前提交」的自然理解），绝不凭空补年份或猜日期。

**验证**：17/17 单元测试通过。

---

### 🟡 Bug 3：设置页填的 AI 地址/模型不生效

**现象**：设置里改了 Base URL 和模型 ID，点保存后视觉识别仍然用内置的 Kilo 模型。

**根因**：`ImportDialog` 里硬编码了 `AiDefaults.VISION_*`，从未读取用户配置。

**修复**：改为优先读设置页配置；只在用户没自定义时才用内置免费模型。
（文字网关默认值会被自动忽略，不会误当成视觉模型使用。）

---

### 🟡 Bug 4：逾期状态不刷新

**现象**：App 一直挂在后台，事项到了截止时间也不会变成「已逾期」，仍显示「还剩 x 天」。

**根因**：`markOverdue()` 只在 App 首次启动时调一次。

**修复**：改用 `repeatOnLifecycle(RESUMED)`，每次回到前台都刷新。

---

### 🟡 Bug 5：代码重复 + 死代码

- `ImportDialog` 里 picker 和 legacyPicker 的整套逻辑复制了两份，容易出现两边行为不一致
  → 已提取共用函数 `runImport(uri)`
- `OcrExtractor.kt`（ML Kit OCR）已被视觉模型取代，无人调用
  → 已删除文件和依赖
- 清理了未使用的 import（`TextSnippet`、`firstOrNull`）

## 五、已知限制（答辩可说明）

1. **免费视觉模型会记录提示**：Kilo 免费池的说明提到可能记录请求内容用于改进，
   课程设计场景可接受；涉及隐私内容不建议使用。
2. **首次识别稍慢**：视觉模型单次调用约 3~8 秒，属于网络往返时间。
3. **需要网络**：视觉识别依赖在线模型，离线不可用（本地 OCR 已移除）。
4. **提醒权限**：Android 12+ 需要手动开启「精确闹钟」权限才能准点提醒。
