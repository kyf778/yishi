## 二、本次主会话做的事

### 1. 视觉模型接入（v0.2.0）

**起因**：你说「无论截图多奇怪、字体多复杂，AI 都能识别出来，但转文字就不够普遍」。

**做的**：
- 废弃「本地 ML Kit OCR → 转文字 → 发给文本模型」两步流程
- 改为**直接把图片发给视觉模型**（Kilo 免费池 `nvidia/nemotron-3.5-super-vl:free`，无需 API key）
- 发现关键坑：Kilo 必须带 `reasoning: {enabled: false}`，否则 `content` 为 `null`

### 2. 长截图识别失败（v0.2.2）—— 你反馈的核心 bug

**现象**：微信群截图识别后报「无法识别有效截止时间」。

**根因**（实测复现）：不是模型问题，是**图片压缩**。老代码按「最长边缩到 1600」：

```
1080×5000 长截图  →  345×1600   ← 宽度只剩 345px，中文全糊
```

**修复**：改成「**宽度优先**」——先保证宽度 ≤1600px（文字清晰），再纵向切块
（每块 ≤1400px，重叠 120px）。
**验证**：1080×9000（切 7 块）也能找到埋在最后一块的消息。

### 3. 日期解析太严格（v0.2.2）

4 类常见格式直接崩：`2026-11-05`（纯日期）、`2026/11/05 11:00`、
`2026-11-05 11:00:00`、`2026年11月5日 11:00`。

**修复**：新建 `DeadlineParser.kt`，支持 8 种格式，纯日期按当天 23:59 处理。17/17 测试通过。

### 4. release 签名包（v0.3.0）

debug 包 57 MB → release 包 **11.76 MB**（小 4.9 倍），用自签 keystore
（`yishi-release.jks`，密码 `<KEYSTORE_PASSWORD>`，别名 `yishi`）。
并把 debug/release 统一签名，避免 Studio 每次运行都要求卸载。

### 5. 界面重设计（v0.4.0）—— 你说「不好看，你看番茄」

**卡片改造**：参考番茄 Todo 做成**渐变主题卡 + 装饰图形**

| 事件类型 | 配色 | 装饰 |
|---|---|---|
| 考试 | 深蓝夜空 | 月牙（Canvas 画两个圆） |
| 作业/提交 | 紫粉渐变 | 流星（斜线+星点） |
| 会议 | 青绿渐变 | 光晕 |
| 逾期 | 红橙渐变 | 警示 |

信息精简为 4 项：标题 / 摘要一行 / 进度条 / 「已过 X/Y 天 · 类型」+ 截止日期。
**踩坑**：固定高度会溢出，改用 `heightIn(min = 128.dp)` 自适应。

### 6. 摘要质量（v0.4.0）—— 你说「总结很草率肤浅」

**根因**：旧提示词只说「提取」，**没说 summary 该写什么**，模型就把原文换个说法重抄。

**修复**：明确禁止三类冗余 + 给正反例。

| | 修复前 | 修复后 |
|---|---|---|
| 标题 | 学委唐林：数据库设计验收与实验报告提交 | **数据库设计验收 + 交实验报告** |
| 摘要 | 学委唐林在群聊中通知全体成员，下周三16点进行… | **需提交实验报告** |

### 7. 短时提醒排不上（v0.5.0）—— 你反馈「10分钟的记录不上」

**根因**：默认提醒是「提前 1 天、提前 1 小时」，代码有 `if (trigger > now)` 过滤 →
10 分钟后的事项，两个 trigger 都已过期 → **提醒数 0**。

**修复**：`adaptiveReminders()` 按剩余时长自适应：

| 剩余 | 提醒 |
|---|---|
| ≤5分钟 | 提前 1 分钟 |
| ≤30分钟 | 提前 5、1 分钟 |
| ≤2小时 | 提前 30、5 分钟 |
| ≤24小时 | 提前 60、10 分钟 |

**实测**：`dumpsys alarm` 确认排入系统 → 到点 `onNotificationPosted` 通知真的弹了。

### 8. 时间显示「0 小时」（v0.5.0）

10 分钟被算成 `remainHours = 0`。改成按量级自动选单位（分钟/小时/天）。
日期也友好化：`2026-10-17 01:30` → **「今天 01:30」**。

### 9. 通知记录（v0.5.0）—— 你说「不知道到时候通知会怎么样」

`notification_log` 表**早就建了但从来没人写入**。现在每次触发落一条：
`已提醒` / `未提醒（缺权限）` / `提醒失败`，新增「提醒记录」标签页。

### 10. 语音输入 —— 做了又删了

**经过**：
1. 先做 `SpeechRecognizer` API 版 → 小米返回 `code=9 权限不足`（**权限明明给了**）
2. 改用 `ACTION_RECOGNIZE_SPEECH` Intent → Activity 启动后**自己关掉**
3. 用 `am start` 命令行直接触发 → **一样被关**
4. 结论：**小米 HyperOS 把语音识别锁给自家「小爱同学」**，不是代码问题
5. 最后**你决定删掉**（说「我会在打字输入的地方用键盘输入法的语音输入」）

**已彻底清理**：按钮、`VoiceInput.kt`、`AudioRecorder.kt`、`AUDIO_*` 常量、
Manifest 权限，全删。现在只有「选择截图 / 打字输入」两个入口。

### 11. WorkBuddy / CodeBuddy 接入（模型新来源）—— 本次最大工程

**起因**：你说「我准备换一个模型，你去研究我免费模型插件，看看怎么接入 workbuddy 的积分，
反正每天 100 积分，还用自己账号」。

**调研**：找到上游 Gitee 仓库 `iJetLi/deepseek-harness-codearts`（MIT），拉下 725 个文件源码。

**关键发现（命名极易混淆）**：

| 插件界面 | 内部 provider | 端点 | productCode |
|---|---|---|---|
| **「WorkBuddy 国内版」** | `buddy` | `www.codebuddy.cn` | **`codebuddy`** |
| 「WorkBuddy 国际版」 | `workbuddy` | `www.workbuddy.ai` | `workbuddy` |

**按你要求**：用**第二个账号**（悲伤玉米排骨汤）+ **国内版**。

**成果**：写了个 480 行的桥服务部署到 NAS，接进已有的公网链：

```
手机(任何网络) → HTTPS → NAS yishi-gateway → free-llm-bridge
                → codebuddy-bridge → www.codebuddy.cn
```

**实测通过**：中文问答 ✅ / 图片识别（正确认出「下周三16点」→ `2026-10-21T16:00`）✅

**CodeBuddy 的五条硬性要求**（全实测踩出，桥已处理）：
1. `stream` 必须为 true（否则 `400 11101`）
2. 必须带一串身份头（`X-Product-Code`、`X-Conversation-*`、`X-IDE-*`）
3. `messages[0]` 必须是 system（否则 `400 11128`）
4. 图片必须和文字在同一条 user 消息里
5. token 会过期，需 `refresh_token` 静默续期

**App 侧改动**：`MODEL` 从 `free-queue` 改成 `hy3`，
`disableReasoning = true`（CodeBuddy 模型默认开思考会吃光 token）。
